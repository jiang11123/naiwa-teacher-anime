# 配音与对齐

画面上每个元素的出场时间都取自配音：分镜里写 `T("013", 1)`（第 013 句第 2 段字幕开始），换配音后重新对齐，画面和音效自动跟着走。所以 **`scripts/lines.json` 是全片的骨架**。

## 1. 拆 lines.json

```json
[
  {"id": "001", "caps": ["同样是用 AI", "有人办订阅，一个月 20 美元"]},
  {"id": "002", "caps": ["结果一查，全是编的"], "marks": ["编的"]}
]
```

- `id`：三位数字，按顺序。中途加句子用 `"012b"` 这类，别重排全片编号
- `caps`：字幕段，按说话的自然停顿拆，每段 ≤ 20 字左右；不到 0.6 秒的碎段并到相邻段
- `marks`：要卡重音的词（盖章、爆点落在这个词上），分镜里用 `M("002", 0)` 取帧
- 英文词之间保留空格，数字写阿拉伯数字（字幕好读）

## 2. 三种配音来源

### A. 用户自己录（默认、最好）

1. 录音放 `public/voice.mp3`。录音结尾如果有“该音频由 AI 生成”之类的话，直接裁掉
2. 转 16k 单声道：

```bash
ffmpeg -y -i public/voice.mp3 -ac 1 -ar 16000 scripts/voice16k.wav
```

3. 识别逐字时间（需要 `pip install funasr modelscope numpy`，首次自动下载中文模型）：

```bash
python scripts/asr.py
```

4. **以录音为准改 lines.json**：对照 `scripts/phrases.json`（每小句识别出的文字），录音漏念的句子删掉、改说的改过来、新加的补上。分镜里对应的画面也一起删 / 改 / 补，不要按稿子补回去
5. 对齐：

```bash
node scripts/align.mjs
```

输出里标了“太短 / 太长”的字幕段逐个查：通常是识别错字或吞了停顿。

**听不清、靠上下文猜的地方，预览时列给用户确认。** 转写出来的英文产品名不要猜（字母缩写最容易被拆错、拼错），拿不准就问。

其他能给逐字时间的 ASR（whisper.cpp、云端接口）也行，只要输出成 `scripts/words.json`：`[[开始毫秒, 结束毫秒, "字"], ...]`。

**为什么不直接用模型给的逐字时间戳**：长音频上会越漂越远。`asr.py` 先按波形里真实的停顿切成小句，每句单独识别，时间取波形起止，所以不会漂。声画对不上时，先切出那一小段重听，别拿同一份数据自证。

### B. TTS 合成

用户本地有 TTS（自己训练的音色、GPT-SoVITS、各家云 TTS 都行）时：

- 按句合成，句与句之间、段落之间、换分镜处要有自然停顿，别一口气连读
- 合成好拼成 `public/voice.mp3`，然后照 A 的 2~5 步对齐
- 真人录音缺了几句，可以用 TTS 补那几句再拼回去，接缝处要听着顺

### C. 还没有配音

```bash
node scripts/estimate-align.mjs
```

按每秒 4.8 字估时间，先把画面做出来给用户看。录好后走 A，画面自动跟着新时间走。估时模式下工程不播放配音（`HAS_VOICE = false`），预览时要告诉用户“现在的节奏是估的”。

## 3. 换配音

用户说“替换这个音频，根据音频改视频”：换 `public/voice.mp3` → 重跑 A 的 2~5 步 → `npx tsc --noEmit` → 抽帧。画面、字幕、音效都跟新录音走；删掉的句子对应的画面、音效、贴纸一起删。

## 4. 录音和稿子的关键差异

录音漏了关键声明（比如“这一步没单独测”），不要假装没事：用画面补一个贴纸，并在预览时告诉用户。

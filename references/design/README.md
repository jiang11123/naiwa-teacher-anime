# 设计判断

这份文件不教你怎么画手绘风——那是 `../style.md`、`../motion.md`、`../components.md` 的事。它管的是**做之前该想清楚什么**：这条视频要让观众完成什么，重点该砸在哪几句，一个东西该留多久，哪些效果是多余的。

判断错了，画得再细也只是精致的废话。这条是过来人的原话：团购那期的画面做得挺细，问题出在信息传达上。

## 什么时候读

不是开工就通读。卡在对应的地方读：

| 你在做哪一步 | 读哪节 |
|---|---|
| 写稿前（主 SKILL.md 第 1 步） | 一、二 |
| 写分镜表前（第 3 步） | 三、四、五、六 |
| 搭画面、定动效（第 4 步） | 七 |
| 抽帧审片（第 5 步） | 八 |
| 用户说"丑 / 呆 / 乱 / 单调" | 八 + `review.md` |

**和主 SKILL.md 的关系：** 主文件管流程和硬约束（几道关、什么时候停），这份文件管每一拍怎么判断。冲突时以主文件的硬约束为准。

## 判断顺序：五层

一条视频的样子由五层决定，上层决定下层，不能倒过来：

| 层 | 问的问题 | 决定什么 |
|---|---|---|
| 任务 | 观众看完要能做到什么？ | 结构、节奏、素材比例 |
| 想法 | 这个题材有什么别人没有的东西？ | 比喻、舞台、亮点 |
| 内容 | 这句话里发生了什么？ | 图形、动作 |
| 风格 | 外观和动势是什么？ | 颜色、线条、质感、手感 |
| 分寸 | 哪些可以不要？ | 数量、时长、强度 |

做得差的视频通常从风格开始：先选好模板，再把内容填进去。这样每种内容最后都长得一样。

**思路对了不等于好看。** 模型靠文字能学会想比喻、定结构，但动起来还是僵硬，还容易把一个东西摆在画面上很久不动。所以七、八两节和前面同样重要，不要写完简报就放松。

## 取舍顺序

两个想法打架时，排在前面的赢。这个顺序不随类型和风格变化：

1. **看得懂**：手机上不暂停，也知道这句在说什么
2. **干净**：不出界、不叠字、不残留，主体清楚
3. **节奏对**：说到它时它出现，动作连贯，停够时间让人看清
4. **有意思**：比喻准，动作有戏，有想截图的点
5. **华丽**：光效、粒子、爆炸

这个顺序只在两个想法打架时用。华丽排最后，不代表能不做就不做：重点句上看得懂和华丽并不冲突，那里要放开做。

## 一、定观众任务和核心

写两句话：

- "看完之后，观众能____"
- "这条视频只讲一件事：____"。一句话说不清，就是还没想清楚，先砍内容

| 观众任务 | 典型视频 | 设计的重心 |
|---|---|---|
| 知道有什么新东西，想去试 | 产品更新、发布 | 快、顺、结果可见 |
| 脑子里建立一个模型 | 概念讲解 | 比喻统一，全动画，慢慢搭 |
| 跟着做成一件事 | 软件教程 | 看得清，不迷路 |
| 相信一个结论 | 数据讲解 | 过程可验证，算给你看 |
| 被说服，或产生共鸣 | 经验、观点 | 情绪起伏，证据和生活比喻 |
| 带走一组能用的东西 | 清单、避坑 | 每项节奏相同，可复制 |
| 追结果，看得爽 | 榜单、锐评 | 固定循环，结果累积 |

讲解是一场论证，不是把内容挨个展示。一条视频可以分段换任务，这时分段设计。具体打法读 `genres.md`。

## 二、从题材里找想法

这一步最能避免"谁都能做出来"的视频。也正是主 SKILL.md 第 1 步要的那个"主比喻"。

**列题材清单：** 写 8~12 个只属于这个题材的东西：物件、数字、场景、行话、反常识的事实、这期台词里提到的具体说法。

**想三个方案：** 全片的核心比喻或舞台，写三个完全不同的方案，每个一句话。第一个想到的通常是平均值，默认淘汰，除非说得出它为什么最好。

**检验比喻：** 观众日常就懂吗？比喻本身还要解释，就换一个。比喻是拿来解释的，不准就是误导，有不准的地方要说出来。

## 三、定结构和重点

结构从任务来，不从模板来。片长决定颗粒度：

- **30 秒以内：** 每句一个分镜，转场 1~2 个，放在最关键的转折
- **1~3 分钟：** 每段字幕一个动作，几个段落
- **3 分钟以上：** 分大段，只在大段开头转场，一期 3~5 个；还要有喘息的地方

节奏跟着张力走：提出问题时快，讲清原理时慢，让观众看清每一步。

**想好前后呼应。** 开头出现过的东西，到后面带着变化回来，观众会觉得这条片子是一个整体。比如开头天平一边是"每月省 70 元"、一边是"你的整个项目"，讲完风险回来时，那一边多了"活断一半""模型掉包"几个砝码。回来的东西要变样，原样再放一次没有意义。它中间可以离开画面，不用一直留着。

**自己从文案里找重点，定好哪里放开。** 不用等用户标。通读全文，给每句定一个等级，写成重点表：

| 等级 | 什么句子 | 画面 | 用多少 |
|---|---|---|---|
| 爆点 | 开头的钩子、大段开头、推翻前面认知的转折、等了很久的揭晓、全片结论 | 整屏都参与：背景、大字、镜头、音效一起来，1~2 秒内收掉 | 30 秒 1 个，1 分钟 1~2 个，更长的片子开头、每个大段开头和结论各 1 个 |
| 重音 | 反差大的数字、金句、这一段的小结、情绪落点 | 主体放大，配一个中等效果 | 每段 1~2 个 |
| 平句 | 铺垫、过渡、第二第三个例子、重复的话 | 只做这句的动作，不加特效 | 其余都是 |

判断时问四个问题：

1. **这句推翻了什么，或者揭晓了什么？** 常带着"但、其实、结果、没想到"，但有这些字不一定是，要看意思
2. **这句删掉，观众任务还能完成吗？** 不能的，至少是重音
3. **观众看完会复述这句吗？** 第 1 步那句"只讲一件事"，通常就是全片结论
4. **这句最该砸在哪个词上？** 爆点要卡在这个词开口的那一帧，不是句子开头。主 SKILL.md 里 `M("011", 0)` 就是干这个的

爆点数量超了就比较，留最重要的，其余降成重音。**平句要真的平，** 爆点前留一小段安静，对比才出得来，所以特效加得匀，就等于没有重点。

举例，一条 5 分钟的"小白别花钱买课"：

| 文案 | 等级 | 为什么 |
|---|---|---|
| 小白学 AI，千万别花钱买课！ | 爆点 | 钩子，反常识 |
| 第一，先行动起来 / 第二…… / 第三…… | 爆点 | 大段开头 |
| 其实学习 AI 真的很简单 | 爆点 | 全片结论 |
| 第一个商单也是靠这个项目拿到的 | 重音 | 证据，情绪落点 |
| 收藏夹里吃灰的教程，永远不会变成你的本事 | 重音 | 金句 |
| 这就像学游泳，在岸上把动作背得滚瓜烂熟 | 平句 | 比方，演出动作就够了 |

## 四、定锚点和轮换

问：**观众靠什么知道自己在哪？** 锚点通常是一种规律，不是摆在屏幕上的物体。

| 类型 | 锚点例子 | 会一直留在画面上吗 |
|---|---|---|
| 榜单 | 榜单本身，一项项填满 | 会，这是例外 |
| 教程 | 同一个软件窗口，加顶部的步骤进度 | 会，这是例外，窗口里的内容要变 |
| 产品更新 | 同一种"名字加证据"的版式，加更新序号 | 版式留下，内容每句换 |
| 概念讲解 | 同一个比喻，比如"一家公司" | 不会。讲实习生就只演实习生，讲前台就换到前台，不把公司全景一直摆着 |
| 数据讲解 | 同一套配色和单位 | 不会 |
| 清单 | 每项相同的节奏 | 不会，每项的物件都换 |

字幕位置和样式全片不动，配色语义也不变。有了这些，观众不会迷路，**物体可以放心地走**。

**再定轮换。** 分镜时给每个主体写清进场和离开的时间。写不出离开时间，它多半会一直留着：

- **提示、标签、箭头：** 约 1.3~3 秒就走
- **主体：** 同一个东西以同样的位置和大小，留约 3~6 秒，之后要离开、被替换、移位或变形
- **大版式：** 一般 6~12 秒换一个
- **上限：** 同样的内容最多留 12 秒，超过了审片脚本判不通过
- **最短：** 切走前至少停留 1.5 秒，观众要看得清

除上限外，这些数字是从一位创作者的成片估出来的，当作起点，观众要读的证据和步骤可以留得更久。测试里有一条片子把同一张桌子放在画面中间约 33 秒，只有桌上的小纸片在变，比喻很准，看起来还是呆。**这个问题在这套 skill 里出现过一次**：一张纸留了 17 秒，看起来还是一张纸。

**超过 12 秒只有两种例外，** 都要提前写进简报，交付时告诉用户：

1. **榜单、清单：** 框架本身就是进度，同时旁边有另一块地方在一直换主体
2. **教程窗口：** 观众在跟着操作，窗口里的内容在换

下面这些理由不算例外：它是这期的舞台、它一直在长大或变形、上面一直在添东西、这样比喻才完整。想保留同一个比喻，就推近、换一段、换一个相关的物件，比喻不会因此断掉。

## 五、定素材和动画的分工

- **事实和证据用真实素材：** 截图、文档原句、官方数据。观众要的是"这是真的"
- **原因和原理用动画：** 截图讲不了"为什么"
- **动手画之前先翻素材，** 能用真的就不要画假的
- **自己画的界面和图表挂"示意"，** 分清文档写的、报道说的、比方、个人理解

比例随任务变：教程可以大半是录屏，但每两三个截图分镜要插一个全屏动画透气；概念讲解可以全动画。

## 六、把内容变成画面

主 SKILL.md 第 3 步的分镜表就是这一步的产物。每段字幕一行，写清三件事：

| 字幕 | 加什么东西 | 它做什么 | 屏上写什么 |
|---|---|---|---|
| 目标太大，你很容易做到一半就放弃 | 进度条 | 涨到一半停住，印章砸上去 | 做到一半·放弃 |
| 想做视频，就先做十秒钟 | 小播放器 | 弹进来，进度条开始走 | 想做视频 → 先做 10 秒 |
| 账号被官方封了，接口说停就停 | 账号卡、任务进度条 | 印章盖上，连线断开，进度变红 | 封号 / 断了，干到一半 |

- **东西要说得出是什么。** 写"卡片""线框""数字"就是还没想好，换成观众认得的东西，或者这个题材里具体的东西
- **屏上的字是字幕的压缩，** 通常 2~8 个字，观众扫一眼就懂。不要复述整句，不要用观众不懂的术语，也不要为了好看加用不上的英文小字
- **相邻几句可以在同一屏上累加，** 加满了再换下一屏。这比一句换一屏更好懂，只是别一直加不换

然后再做这几件事。

**句子里有动作，就演动作。** 找动词 → 找一个物件 → 做完整因果（起势、发生、结果）。说"拿走"就要真的飞出屏幕。

**句子里有关系，就画关系。** 比例画格子，累积画阶梯，定义画等式，先后画流程。别一律做成文字卡。

**组件之外也要有事发生。** 背景、物件、动作留下的结果、爆点字，这四层逐段过一遍，写成效果表：第几秒、什么效果、绑定哪个动作。只有卡片在弹，画面还是素的。具体怎么选读 `effects.md`。

**让事情落到谁身上。** 讲解最容易只剩信息，没有情绪。每期先想一个有反应的角色：代表观众的"你"，或者这个题材里会受影响的东西。说到坏事它就变脸，说到好处它就高兴。这套 skill 的 `Person` 可以传 `mood` 和 `label="你"`。不用角色就写明理由，并说清情绪靠什么传达，比如印章砸下、东西碎掉。

## 七、动势和手感

**风格已经由主 SKILL.md 定死**（纸手绘、Q 弹、线条抖动），这里不再选风格。要判断的只有两件事：**该不该动，动多大**。

要落地的具体曲线、帧数、`kind` 选择、镜头写法，全部在 `../motion.md`。这里只给判断：

- **主动作、跟随、环境三层都要有。** 东西落下时，旁边的东西要有反应。只有元素自己弹，画面就是一张张飘进来的卡片
- **上一个走，下一个紧接着来。** 用 `A` 的 `out` 做退场，不要写 `frame < N` 删东西，那样退场来不及播
- **大段落之间要有转场，** 但只在 2D 平面模式下必做；3D 展板和实景靠镜头走
- **爆点要放开做。** 拿不准会不会太夸张，就先做夸张，看了再收
- **镜头不走回头路。** 同一个主体跨分镜时接着走，不缩回去再推
- **主体要大。** 主角占不到可用高度一半就放大
- **先渲染几张单帧确认，** 再导出全片

**这些是风格选项，不是审美标准：** 线条抖动强度、纸纹粗细、回弹多少、圆角大小。判断元素对不对只看它和这套风格是否一致（见 `style-systems.md`）。

## 八、看图审片

审美主要靠看。每一轮修改后都检查。主 SKILL.md 第 5 步用 `check.mjs` 抽帧，成片后用 `scripts/review.mjs` 算停留率。方法、数据参考线、真实被否决的版本，都在 `review.md`。

三条底线：

- **脚本提示"不通过"就不能交付。** 同样的内容留过 12 秒，先改画面
- **爆点也要查。** 不够大、或者全片没有一处整屏参与的变化，都算不合格
- **做不到看图，就明说没有看过。** 不要声称画面没问题，也不要自己宣布"动效很 Q 弹"

## 规则会随类型翻转

下面这些"规则"都只在某些视频里成立。照搬比不知道更糟。

| 问题 | 这样对 | 那样也对 | 判断依据 |
|---|---|---|---|
| 居中还是左右排？ | 讲解内容居中，一次一个主体 | 产品更新"左边名字、右边证据"，全片稳定 | 两边是否真有"名字—证据"或"A—B"的关系。忌讳的是左边标题、右边要点列表 |
| 画面要多满、多动？ | 无人物 MG：整屏都动 | 榜单：榜单几乎不动，只有当前一项在动 | 观众在追榜单、跟窗口操作时可以安静，其他情况靠轮换撑 |
| 回弹多少？ | 轻松讲解：明显回弹 | 严肃内容：基本不弹 | 风格的动势和内容情绪 |
| 转场多少？ | 几分钟的片子 3~5 个 | 25 秒的片子 1~2 个 | 片长和段落数 |
| 分镜之间怎么接？ | 长讲解：上一个走、下一个接，段落处转场 | 产品更新：元素变形接下一句 | 观众任务是"顺"还是"分段理解" |
| 一个东西留多久？ | 主体约 3~6 秒就走或变，不静止超过 3 秒 | 榜单、教程窗口：框架可以留，里面的内容要换；截图停留时另一侧要有小动画 | 观众是否需要读，或这个东西是否就是进度本身 |
| 要不要真实截图？ | 教程、证据：必须 | 讲原因时：不要硬放 | 这句话是事实还是原理 |
| 要不要人物？ | 同学替观众提问、主讲串场、"你"跟着事情变脸 | 没有信息量时不放，用大字图形补 | 人物这一刻有没有事做、有没有反应 |
| 音效风格 | 产品更新：惊喜感 | 讲解：只做点缀 | 观众任务 |

遇到规则冲突时，回到观众任务和取舍顺序自己判断，把理由写进简报。

## 跨类型都不变的事

- **一帧一个主角。** 说不出主角是谁，就减东西。主角太小就放大，不要加东西填空
- **基本单位是字幕段。** 每段都有动作或变化，东西在说到时出现
- **画面不复述字幕。** 字幕念整句，画面放关键词、数字、结论、动作
- **按手机算大小。** 手机上看不清的字等于没有
- **颜色有语义。** 同一个意思全片同一个颜色，强调色只给强调
- **该退就退。** 提示用完就走，上一步不残留。比喻可以贯穿全片，物体不用
- **夸张要有对比。** 重点句放开做，其余收着。一直夸张就等于没有夸张，一直保守就没有记忆点。不做一直闪、一直转的东西
- **诚实。** 好看不能靠编，隐私要打码
- **每期有新东西。** 风格可以沿用，转场、道具、封面每期新做，且贴内容
- **用户的反馈优先。** 用户说丑就是丑。问清楚哪里不对，修细节，别整体推翻，也别改掉用户说好的部分

## 设计简报模板

分镜之前写好，放在工程根目录的 `storyboard.md` 开头（主 SKILL.md 第 3 步）。简短，每项一两句。

```markdown
# 设计简报

**观众任务：** 看完之后，观众能____
**只讲一件事：** ____
**类型与片长：** ____（横屏 / 竖屏）
**画面模式：** 3D 展板 / 2D 平面 / 3D 实景，为什么（用户选的还是我推荐的）
**题材清单：** 8~12 个只属于这个题材的东西
**三个方案：** ①__ ②__ ③__ → 选 __，因为____
**结构：** 开头怎么抓人 → 中间几段 → 结尾怎么收
```
